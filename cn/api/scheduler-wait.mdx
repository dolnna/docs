---
title: '调度器等待 —— POST /product/scheduler/wait'
description: '阻塞直到调度器完成某用户的所有任务，或通过 SSE 流式实时进度事件直到队列空闲或达到超时。'
---

在异步记忆操作（如 `POST /product/add`）之后，您有时需要在发起搜索或运行评估之前知道所有后台处理何时完成。wait 端点提供两种方式：一个阻塞 POST，仅在调度器空闲时返回；以及一个流式 GET，以 SSE 流的形式发出实时进度事件。阻塞等待是脚本、测试和顺序流水线最简单的选择。流式变体更适合您希望在调度器工作时显示实时指示器的进度 UI。

<Warning>
  这两个端点会在紧密循环中轮询调度器并保持开放连接，直到空闲或超时。对于具有许多并发用户的生产负载，请按您自己的节奏轮询 [GET /product/scheduler/status](/cn/api/scheduler-status)，以避免保持长时间存在的服务器连接。
</Warning>

## 端点

| 方法 | 路径 | 用途 |
|--------|------|---------|
| `POST` | `/product/scheduler/wait` | 阻塞直到空闲，然后返回摘要 |
| `GET` | `/product/scheduler/wait/stream` | 流式 SSE 进度事件直到空闲 |

---

## POST /product/scheduler/wait

阻塞 HTTP 连接并轮询调度器，直到该用户的所有任务达到终止状态（`completed`、`failed` 或 `cancelled`），或超时到期。

### 查询参数

<ParamField query="user_name" type="string" required>
  要等待的用户名（或用户 ID）。必须与提交任务时使用的标识符匹配。
</ParamField>

<ParamField query="timeout_seconds" type="number" default="120">
  返回超时结果前等待的最大秒数。服务器在调度器变为空闲或达到此限制时（以先到者为准）返回响应。
</ParamField>

<ParamField query="poll_interval" type="number" default="0.5">
  服务器内部检查任务状态的频率（秒）。较低的值减少延迟但增加服务器端 CPU 使用率。不推荐低于 `0.1` 的值。
</ParamField>

### 响应

<ResponseField name="message" type="string" required>
  所有任务在超时前完成时为 `"idle"`。等待期满但仍有任务活动时为 `"timeout"`。
</ResponseField>

<ResponseField name="data" type="object" required>
  等待操作的摘要。

  <Expandable title="data object">
    <ResponseField name="data.running_tasks" type="integer" required>
      响应发送时仍处于 `"waiting"` 或 `"in_progress"` 状态的任务数。当调度器达到空闲时为 `0`。
    </ResponseField>
    <ResponseField name="data.waited_seconds" type="number" required>
      从请求收到到响应发送的总耗时（秒）。
    </ResponseField>
    <ResponseField name="data.timed_out" type="boolean" required>
      当响应是由超时而非空闲状态触发时为 `true`。
    </ResponseField>
    <ResponseField name="data.user_name" type="string" required>
      等待所限定的用户名。
    </ResponseField>
  </Expandable>
</ResponseField>

### 示例

#### 在搜索前等待异步 add 完成

```python Python
import requests

BASE_URL = "http://localhost:8000"
USER_ID = "8736b16e-1d20-4163-980b-a5063c3facdc"
CUBE_ID = "b32d0977-435d-4828-a86f-4f47f8b55bca"

# Step 1: submit an async memory add
add_resp = requests.post(
    f"{BASE_URL}/product/add",
    json={
        "user_id": USER_ID,
        "writable_cube_ids": [CUBE_ID],
        "messages": [
            {"role": "user", "content": "I prefer aisle seats when flying."},
            {"role": "assistant", "content": "Noted, I will remember your seating preference."},
        ],
        "async_mode": "async",
    },
)
add_resp.raise_for_status()
print("Add enqueued:", add_resp.json()["data"]["task_id"])

# Step 2: wait until the scheduler processes all tasks for this user
wait_resp = requests.post(
    f"{BASE_URL}/product/scheduler/wait",
    params={
        "user_name": USER_ID,
        "timeout_seconds": 60,
        "poll_interval": 0.5,
    },
)
wait_resp.raise_for_status()
result = wait_resp.json()
print(f"Scheduler status: {result['message']} (waited {result['data']['waited_seconds']}s)")

# Step 3: now search — memory is guaranteed to be written
search_resp = requests.post(
    f"{BASE_URL}/product/search",
    json={
        "user_id": USER_ID,
        "query": "What are my flight preferences?",
        "readable_cube_ids": [CUBE_ID],
    },
)
print(search_resp.json())
```

## GET /product/scheduler/wait/stream

将实时调度器进度作为 Server-Sent Events 流式传输，直到调度器对指定用户变为空闲或超时到期。每个事件携带当前活动任务数和已用时间，因此您可以在 UI 中驱动进度指示器。

### 查询参数

<ParamField query="user_name" type="string" required>
  要监控的用户名（或用户 ID）。
</ParamField>

<ParamField query="timeout_seconds" type="number" default="120">
  流的最大持续时间（秒）。如果达到此限制，将在流关闭之前发出带 `"status": "timeout"` 的最终事件。
</ParamField>

<ParamField query="poll_interval" type="number" default="0.5">
  服务器端状态检查之间的间隔（秒）。
</ParamField>

### SSE 事件格式

每个事件是一个 `data:` 行后跟一个 JSON 对象，并通过空白行与下一个事件分隔。

<ResponseField name="user_name" type="string" required>
  此事件所限定的用户名。
</ResponseField>

<ResponseField name="active_tasks" type="integer" required>
  当前处于 `"waiting"` 或 `"in_progress"` 状态的任务数。调度器空闲时为 `0`。
</ResponseField>

<ResponseField name="elapsed_seconds" type="number" required>
  自流开始以来经过的秒数。
</ResponseField>

<ResponseField name="status" type="string" required>
  任务活动时为 `"running"`。所有任务完成时为 `"idle"`。达到超时时为 `"timeout"`。发生内部错误时为 `"error"`。
</ResponseField>

<ResponseField name="timed_out" type="boolean">
  仅在最终的 `"timeout"` 事件中存在。当流因超时结束时为 `true`。
</ResponseField>

<ResponseField name="instance_id" type="string">
  服务器实例标识符，在调试多实例部署时很有用。
</ResponseField>

### 示例

<CodeGroup>

```bash cURL
curl --no-buffer \
  "http://localhost:8000/product/scheduler/wait/stream?user_name=8736b16e-1d20-4163-980b-a5063c3facdc&timeout_seconds=60"
```

```python Python
import json
import requests

response = requests.get(
    "http://localhost:8000/product/scheduler/wait/stream",
    params={
        "user_name": "8736b16e-1d20-4163-980b-a5063c3facdc",
        "timeout_seconds": 60,
    },
    stream=True,
)

for line in response.iter_lines():
    if not line:
        continue
    text = line.decode("utf-8")
    if not text.startswith("data: "):
        continue
    event = json.loads(text[len("data: "):])
    print(
        f"status={event['status']} "
        f"active={event['active_tasks']} "
        f"elapsed={event['elapsed_seconds']:.1f}s"
    )
    if event["status"] in ("idle", "timeout", "error"):
        break
```

## 错误响应

| Code | 描述 |
|------|-------------|
| `422` | 验证错误 —— 必需的查询参数缺失或类型错误。 |
| `500` | 在轮询任务状态时发生内部错误。对于流端点，错误作为 `{"status": "error", ...}` SSE 事件递送，而非 HTTP 状态码。 |

```json 422
{
  "detail": [
    {
      "type": "missing",
      "loc": ["query", "user_name"],
      "msg": "Field required",
      "input": {}
    }
  ]
}
```

流内错误如下所示：

```
data: {"status": "error", "detail": "stream_failed", "exception": "Redis connection lost", "user_name": "8736b16e-1d20-4163-980b-a5063c3facdc"}
```
