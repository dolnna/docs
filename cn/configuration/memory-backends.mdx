---
title: "为 MemOS 选择记忆后端"
description: "比较三种 MemOS 文本记忆后端 —— naive_text、general_text 和 tree_text —— 并了解何时为您的部署使用每一种。"
---

MemOS 将文本记忆存储在三种后端之一，每种后端都有不同的存储引擎、检索能力和设置复杂度。您通过设置 `MOS_TEXT_MEM_TYPE` 环境变量来选择后端。正确的选择取决于您的规模、记忆中需要多少关系结构，以及您愿意管理多少基础设施。

---

## 后端比较

| | `naive_text` | `general_text` | `tree_text` |
|---|---|---|---|
| **存储引擎** | SQLite | Qdrant | Neo4j |
| **设置复杂度** | 无 | 中等（需要 Qdrant） | 较高（需要 Neo4j） |
| **规模** | 开发、小型部署 | 生产、大规模 | 生产、关系型记忆 |
| **检索** | FTS5 关键词 + 基础向量 | 语义向量 + FTS5 | 图遍历 + 向量 |
| **关系型记忆** | 否 | 否 | 是 |
| **额外服务** | 无 | Qdrant | Neo4j + Qdrant（社区版） |
| **最适合** | 上手、本地开发 | 多数生产场景 | 复杂的 Agent 记忆、多跳推理 |

---

## `naive_text` —— SQLite，零设置

`naive_text` 使用 SQLite 进行存储和检索。无需外部服务。它是让 MemOS 运行起来最快的方式，非常适合开发、评估和低流量部署。

```env
MOS_TEXT_MEM_TYPE=naive_text
```

检索使用 FTS5 全文搜索结合本地计算的基础向量相似度。这对小型记忆存储足够，但在大规模时精度和速度会下降。

<Tip>
  首次评估 MemOS 或构建原型时，从 `naive_text` 开始。之后可以在不更改应用代码的情况下迁移到 `general_text` 或 `tree_text`。
</Tip>

---

## `general_text` —— Qdrant，生产就绪的语义搜索

`general_text` 将记忆向量存储在 [Qdrant](https://qdrant.tech/) 中，这是一个专门构建的向量数据库。它提供快速、高精度的语义搜索，并能扩展到数百万条记忆记录而不降低性能。

```env
MOS_TEXT_MEM_TYPE=general_text
```

在启动 MemOS 之前，您需要一个运行中的 Qdrant 实例。最快的方式是 Docker：

```bash
docker run -p 6333:6333 qdrant/qdrant
```

然后配置您的嵌入器变量，以便 MemOS 可以创建和查询向量集合：

```env
MOS_EMBEDDER_BACKEND=universal_api
MOS_EMBEDDER_MODEL=text-embedding-v4
MOS_EMBEDDER_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
MOS_EMBEDDER_API_KEY=your-api-key
EMBEDDING_DIMENSION=1024
```

`general_text` 是大多数生产部署的推荐后端。它提供语义搜索，且没有 `tree_text` 的图基础设施复杂性。

---

## `tree_text` —— Neo4j，关系图记忆

`tree_text` 将记忆作为图存储在 [Neo4j](https://neo4j.com/) 中。记忆通过关系连接，支持多跳推理、因果链接和层次化记忆结构。对于需要理解记忆之间关系的 Agent，这是最强大的后端。

```env
MOS_TEXT_MEM_TYPE=tree_text
```

您需要一个运行中的 Neo4j 实例。安装 [Neo4j Desktop](https://neo4j.com/download/) 或通过 Docker 运行：

```bash
docker run \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/your-password \
  neo4j:latest
```

然后配置 Neo4j 连接变量：

```env
NEO4J_BACKEND=neo4j-community
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your-password
NEO4J_DB_NAME=neo4j
```

<Note>
  除非您拥有 Neo4j 企业版许可证，否则请使用 `NEO4J_BACKEND=neo4j-community`。社区版后端使用 Qdrant 进行向量索引（因为社区版不支持原生向量索引），因此当将 `tree_text` 与 `neo4j-community` 一起使用时，您还需要一个运行中的 Qdrant 实例。
</Note>

### 何时使用 `tree_text`

当您的 Agent 需要满足以下条件时，选择 `tree_text`：

- 在记忆之间遍历关系（例如，"哪些决策导致了这个结果"）
- 在实体之间维护带类型化关系的结构化世界模型
- 通过检测图中冲突的节点来去重记忆
- 支持多个用户共享一个 Neo4j 数据库且通过 `user_name` 进行逻辑隔离的多租户部署

---

## 多租户共享数据库

`general_text` 和 `tree_text` 都支持多用户共享一个数据库的多租户部署。使用以下设置启用共享模式：

```env
MOS_NEO4J_SHARED_DB=true   # for tree_text
```

在共享模式下，每个用户的记忆通过其 `user_id` 隔离。所有读取、写入和搜索都会自动按 `user_id` 过滤，因此用户永远不会看到彼此的数据。

---

## 重排器选项

在主要检索步骤之后，MemOS 可选地对结果重排以改进最终的相关性排序。独立于记忆后端配置重排器：

| 值 | 描述 |
|---|---|
| `cosine_local` | 默认。使用本地余弦相似度计算重排。无需额外服务。 |
| `http_bge` | 使用外部 BGE 重排器 HTTP 服务。以增加一个服务依赖为代价提供更高质量的重排。 |

```env
MOS_RERANKER_BACKEND=cosine_local
```

仅当您部署了 BGE 重排器且需要最大检索精度时才使用 `http_bge`。
